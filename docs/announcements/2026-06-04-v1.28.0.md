# memory-kernel 1.28.0 — now on npm

`memory-kernel` is a persistent, typed memory layer for AI agents. It stores durable atoms (facts, decisions, beliefs, preferences, constraints, …) as markdown files with YAML frontmatter, indexed in SQLite for FTS5 + optional embedding-based recall, and exposed through three integration paths: a CLI (`mk`), an MCP server (`mk-mcp`), and the `openclaw-memory-kernel` plugin (in-tree at `packages/openclaw-memory-kernel/`, scheduled for its own first npm publish on the `openclaw-memory-kernel-v*` tag track per [#197](https://github.com/mainion-ai/memory-kernel-dev/issues/197) once subpackage OIDC trusted publisher is configured on npmjs.com).

The source has been public at [`mainion-ai/memory-kernel`](https://github.com/mainion-ai/memory-kernel) since early 2026 and existing pinners can `git pull` cleanly to v1.28.0 (the synthetic squash commit is parented to v1.16.1 — no force-reset). What's new in v1.28.0 is that **memory-kernel is now installable via npm with a signed sigstore SLSA-v1 provenance attestation** tied to the GitHub Actions release workflow.

## Install

```bash
npm install -g memory-kernel
mk --version  # 1.28.0
```

Or programmatic:

```bash
npm install memory-kernel
```

Verify the provenance attestation against sigstore's transparency log:

```bash
npm audit signatures memory-kernel
# expect: "verified registry signatures" + "verified attestations"
```

## What's in 1.28.0

A few of the load-bearing capabilities, distilled — there is more in the README + `docs/`:

- **Honest recall.** `mk recall --task "<query>"` returns atoms that actually match the query (FTS5 + optional embedding hybrid). On no match, recall returns `atoms: []` + `recall_status: "no_match"` — agents get a clean abstention signal instead of a hallucination scaffold of confidently-irrelevant fallback atoms. Validated against [LongMemEval](https://github.com/xiaowu0162/LongMemEval): **41.4% overall** at v1.26.1, slightly above the published BM25 reference of ~38%. v1.27.0 added the no-match semantics; v1.28.0 added `mk extract --preference-pass` for sharper preference-atom extraction (LongMemEval re-run pending on the new baseline).
- **Event-sourced.** Every state-changing operation is logged to `events.ndjson`. The on-disk markdown is rebuilt deterministically from the event log via `mk replay`. Audit trails, time-travel, debugging.
- **Per-agent isolation.** Two modes: `shared` (everything visible to every agent) and `per-agent` (each agent gets its own namespace, with explicit cross-agent share via `mk share`). Useful for multi-agent systems where one agent's beliefs shouldn't pollute another's recall.
- **Atomic supersession.** Facts can be superseded (with audit trail); beliefs can promote to facts at confidence ≥ 0.9; conflicts get detected and surfaced via `mk list-conflicts`. The supersession chain is rendered in atom files so an external tool (Obsidian, your editor) can see the lineage without consulting the SQLite index.
- **MCP server out of the box.** `mk-mcp` exposes the same tools to any MCP client (Claude Desktop, Cursor, Continue, …). Drop-in.
- **Doctor + reflect.** `mk doctor` surfaces store-level issues with `--fix` + `--dry-run` modes (idempotent — only touches non-content metadata: index reindex, file permissions, render config, atom-schema migrations). `mk reflect` performs lifecycle maintenance (deduplication, expiry, view regeneration).

## Quality posture

**1672 tests passing across 114 files** as of this release. Tests cover the CLI surface (every `mk` command with `--json` contract checks), the SDK surface (`recall`, `wander`, `reflect`, `extract`, …), the index path (FTS5 + embeddings + relations + citations), the doctor checks, the privacy sync mechanism, and a handful of end-to-end integration suites against real memory directories. Privacy scanner + docs-hygiene gate run on every PR.
