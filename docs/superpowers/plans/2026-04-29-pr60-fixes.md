# PR #60 follow-up fixes — v1.17.1 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the ten issues identified in code review of [PR #60](https://github.com/mainion-ai/memory-kernel-dev/pull/60), ship as `v1.17.1` (PATCH — bug fixes + tightening, no public API additions).

**Architecture:** Two correctness fixes (`mk wander --as-of` event-pre-filter and shared-namespace inclusion) plus eight smaller hardening changes (option-injected `now` in wander, single-write retain, schema bounds, validation, UX). Shared namespace replay reuses the existing `replayFromFile` + filter pattern, then concatenates atom lists with agent-wins-on-ID-collision precedence (mirroring `wanderFromFiles` line 718-723).

**Tech Stack:** TypeScript, vitest, Commander.js (CLI), Zod (schema), better-sqlite3 (existing index, untouched).

## Task 2: Fix `--as-of` to pre-filter events and replay shared namespace (review issues #1, #2)

**Files:**
- Modify: `src/cli/mk.ts:1022-1058` (the `--as-of` branch in `mk wander`)

The fix has three parts:
1. Read `events.ndjson`, filter by `line.timestamp <= asOf`, then call `replay()` on the filtered events. This produces correct point-in-time atom state.
2. If `sharedMemoryDir` exists, do the same for shared `events.ndjson` and concatenate atom arrays.
3. Pass agent-then-shared concat order so `buildGraphFromAtomList` lets agent atoms win on ID collision (mirrors `wanderFromFiles` lines 718-723: `if (!graph.has(id)) graph.set(id, node)`).
